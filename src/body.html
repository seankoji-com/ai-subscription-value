The method

How the numbers are calculated

Read the full method formulas and effort curves

Every point is one model at one effort level, on one subscription plan. Five numbers produce its position: a score, an API cost per task and a time per task from the benchmark, a plan capacity, and a plan price.

1. Score

The score is the Artificial Analysis Coding Agent Index v2.0: the plain average of three pass rates, each run in the model's own agent harness.

  • FrontierCode v1.1: writing code changes to real repositories (partial credit allowed).
  • Terminal-Bench 4.0: multi-step tasks in a terminal. This is the closest of the three to hands-on agent work.
  • SWE-Atlas QnA: answering questions about a codebase by reading it.

Example: DeepSeek V4.1 Flash scores (46.55 + 30.81 + 61.56) ÷ 3 ≈ 46.3. GPT-6.1 Terra medium scores (43.75 + 35.35 + 47.04) ÷ 3 ≈ 42.0. DeepSeek's lead comes almost entirely from SWE-Atlas QnA; Terra medium is ahead on Terminal-Bench. Each benchmark has a few dozen to about 100 tasks, so differences of a few points are within run-to-run noise.

2. API cost and time per task

AA measures what one attempt at one task costs at pay-per-token API prices (input, cached input, cache writes and output, at list price) and how long the agent runs. Both are averages over every attempt, failures included.

3. Plan capacity

Capacity is the API-equivalent dollars of use a plan allows per month at 100% of its weekly cap. OpenCode Go is the exception that publishes this directly, as a monthly dollar allowance per model (for example $100 for DeepSeek V4.1 Flash), and those allowances are used as-is. The other providers publish no limits in tokens or dollars. Third parties measure it by watching a plan's usage meter rise while pricing the same traffic at API rates: if $50 of API-priced work moves the weekly meter by 5%, the week is worth $1,000. Weekly figures are multiplied by 52 ÷ 12 to get a month. The plans table lists the source for every plan, and models without their own measurement use the plan-wide figure.

4. Tasks per month and cost per task

tasks per month = plan capacity ÷ API cost per task
subscription cost per task = plan price ÷ tasks per month

Example: Opus 5.5 max on Claude Ultra. Capacity $1,549/week × 52 ÷ 12 = $6,712/month. AA's API cost is $11.42 per task, so $6,712 ÷ $11.42 ≈ 588 tasks a month, and $200 ÷ 588 ≈ $0.340 per task.

Because both formulas divide by the same API cost, cost per task is really plan price × API cost ÷ capacity. A model that is cheap at API prices is cheap on any plan that meters it at those prices. Providers don't promise to meter that way.

6. Evidence grades

  • Measured (filled badge): a capacity measurement that includes this model's traffic, and an AA row in the plan's own harness.
  • Inferred (hollow badge): capacity measured for other models on the plan, a scaled scenario, a benchmark run in a different harness, or an effort level rescaled from the older snapshot.
  • Modelled (dashed badge): no published benchmark at that effort level, or no API price.
