Valued at 100% of each plan's weekly cap. Benchmark: AA Coding Agent Index v2.0 (27 Oct 2026). Plans: the top plan from each provider, and OpenCode Go for models without one. Data as of 4 Nov 2026; page built __BUILT__.

Plans and capacity

Gaps

  • Muse capacity is assumed. Meta publishes Muse Code limits only as prompts per 5 hours (Maximum = 80× Everyday), so Muse Code Maximum ($200) is assumed to return the same API-equivalent value per dollar as Claude Ultra's measured $1,549/wk. Muse Spark 1.3 and Muse Wonder use AA's measured API cost. Muse Wonder Full has no API price (AA lists $0.00), so its tokens are priced at Fable 5.1's cost per token and it is drawn as modelled.
  • DeepSeek and Kimi come through OpenCode Go. They have no top plan of their own here, so they use OpenCode Go ($10) with its published per-model allowances. Their logos show the model maker. Kimi K3.1 Pro isn't plotted: AA hasn't published a coding-agent row for it.
  • Gemini has no measured capacity. Google publishes no Antigravity quota. The plotted capacity is a September scenario for the Ultra 5× tier ($1,890–$5,671/month), scaled 4× for Ultra 20×. Gemini 4 Carbon scores 59 on Antigravity but isn't generally available and has no cost or time row yet.
  • Grok rests on one receipt. SuperGrok Heavy capacity comes from one account's meter movement. SuperGrok ($30) has no measurement, so there's no way to tell which Grok plan is better value.
  • OpenCode harness mismatch. AA tested OpenCode only with GLM-5.3, and GLM-5.3 isn't in Go's published list. Every Go point therefore uses another harness's benchmark row as a proxy.
  • Effort levels. The coding-agent index (v2.0) tests Claude models and GPT-6.1 Sol at max only. Sonnet 5.5 and Sol at low–xhigh come from AA's 5 Oct snapshot, rescaled to v2.0 through each model's max row, and are graded inferred. Opus 5.5 at low–xhigh is modelled from Anthropic's own effort curve: cost from its SWE-bench Pro subset ($0.11 low, $0.21 medium, $0.29 high, $0.74 xhigh per task), score from the average of its SWE-bench Pro and Terminal-Bench 4.0 results relative to xhigh, and time from AA's Opus tokens per task at each effort. Anthropic publishes no max row, so the xhigh→max step uses AA's own Opus effort data (cost ×1.66, score ×1.047). These points are drawn with a dashed ring and never recommended. Where AA's Intelligence Index ran a model at every effort (Fable, Haiku, Astra, Luna, Grok), its effort curve is applied to the coding row; those points are modelled too.

Method

  • Tasks per month = monthly API-equivalent capacity ÷ AA API cost per task. Weekly measurements are scaled by 52/12.
  • Subscription $/task = plan price ÷ tasks per month. An earlier version divided this by the score to get "$ per success". That treated the score as a retry rate, as if every failed task would eventually pass, and it made cheap weak models (Luna low) look best. The main chart now plots cost against time and uses the score only as a minimum you set.
  • Evidence grades. Measured: a third-party capacity measurement that includes this model's traffic, plus an AA v2.0 row in the plan's own harness. Inferred: plan-level capacity applied to a model outside the measured mix, a scaled scenario, a proxy harness, or an effort row rescaled from the older snapshot. Modelled: no published benchmark at all, estimated from a sibling model. Only measured points are recommended.
  • Caveat. Every capacity figure is an estimate from a third party or a scenario. None comes from a vendor contract. The method assumes a plan meters each model at its API price, which providers don't promise: wokey reports that Opus 5.5 uses about 0.6× the limit per token of other Opus models. Five-hour windows are ignored; the report assumes 100% of the weekly cap is used.
